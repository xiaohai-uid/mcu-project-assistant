# 嘉立创产品经验对个人版 MCU 助手的借鉴

## 结论

嘉立创最值得借鉴的不是“大而全”，而是把一个器件从“模糊名称”变成一条可追溯的采购和设计记录：精确型号、封装、BOM 编号、价格、库存、替代型号和下单入口彼此关联。

个人版只需要做这条链路的窄版本：

`项目需求 → 精确器件身份 → 官方资料 → 接线/封装约束 → 观察到的价格与库存 → 可复查 BOM`

不做嘉立创的完整商城、PCB 制造、SMT 贴片、百万级库或企业采购系统。

## 官方资料中可借鉴的做法

### 1. 用精确商品身份连接设计与采购

嘉立创EDA的官方指南说明，元件库可以使用立创商城引擎按商品信息和参数选型；BOM 中可以分配立创商城的零件编号，之后检查库存或进入商城购买，也可以更换型号。[官方元件库指南](https://docs.lceda.cn/cn/Schematic/Libraries/index.html)、[官方BOM导出指南](https://docs.lceda.cn/Schematic/Export-BOM/index.html)、[官方下单流程](https://docs.lceda.cn/cn/PCB/Order-PCB/index.html)

个人版应借鉴为：

- 用户看到的是精确的品牌、型号、版本和供应商编号，而不是只显示“温湿度传感器”“继电器模块”；
- 每一条 BOM 行都能回到对应的器件身份、官方资料和接线限制；
- 替代型号单独列为“候选”，不能自动变成原型号；
- 可以导出一份简单 BOM，但不承担自动下单责任。

### 2. 把价格和库存当作带时间的观察

官方流程把“购买元件/检查库存”作为 BOM 后续动作，并提醒立创商城库存/价格与嘉立创贴片库存/价格是独立的。[官方下单流程](https://docs.lceda.cn/cn/PCB/Order-PCB/index.html)

个人版应借鉴为：

- 价格、库存、起订量、运费和查询时间放在同一条观察记录里；
- 不把不同商城或不同数量档位混成一个价格；
- 价格只影响采购建议和成本估算，不影响芯片兼容性、接线安全或“是否能运行”的判断；
- 没有可靠库存数据时显示“未观察到库存”，不显示“有货”。

### 3. BOM 是独立且可复查的结果

官方指南明确区分原理图 BOM 和 PCB BOM，并支持导出 CSV；价格列取当前商城的第一阶梯单价。[官方BOM导出指南](https://docs.lceda.cn/Schematic/Export-BOM/index.html)

个人版应借鉴为：

- 保存用户输入的 BOM 与系统生成的推荐 BOM 两份记录；
- 每行保留数量、精确型号、替代候选、来源、价格观察和状态；
- 导出结果必须带查询日期，不能让用户以为价格永久有效；
- 先做 CSV/Markdown 导出，不做商城账号和自动订单接口。

### 4. 资料库要有版本，不要假装永远正确

嘉立创官方文档说明，符号和封装库有历史版本机制，以避免后续库修改悄悄改变旧工程；同时也提醒系统库可能存在错误，生产前应检查封装，尤其是用户贡献库。[官方元件库指南](https://docs.lceda.cn/cn/Schematic/Libraries/index.html)

个人版应借鉴为：

- 记录资料来源版本、查询时间和数据状态；
- 对旧工程固定当时使用的器件资料，不自动替换；
- 用户贡献或推断内容必须单独标记，不能与厂家资料混在一起；
- 对“官方资料未给出”的参数保持未知，不用常见经验值补全。

## 个人开发者版的最小产品形态

### 一个器件卡片

每张卡片只解决一个问题：这个东西到底是什么、能不能用、为什么这样判断。

最少包括：

- 精确身份：品牌、型号、料号、对象层级（芯片/模组/开发板/模块）；
- 官方资料：链接、文档版本、查询日期；
- 关键参数：数值、单位、条件和参数性质；
- 连接限制：供电、逻辑电平、占用引脚、不能接的情况；
- 采购观察：价格、数量档、库存、来源、时间；
- 状态：已找到、官方资料已核对、价格已观察、已编译、已上传、已实物观察；
- 替代型号：候选、原因、未确认的差异。

### 一个小型 BOM 工作流

首版只需要支持：

1. 用户输入“我要做什么”和已有器件；
2. 系统推荐精确型号，并说明理由；
3. 用户确认后生成 BOM；
4. 系统显示来源、价格观察和缺失资料；
5. 导出 CSV/Markdown，用户自行购买。

### 明确不做的部分

- 不建设百万级通用库；
- 不做完整 PCB 绘图和制造平台；
- 不接入商城账号、支付和自动下单；
- 不把实时库存承诺给用户；
- 不因某个价格更低就自动替换器件；
- 不把商城库或仿真通过当成实物验证。

## 对 MCU Project Assistant 的直接调整建议

首发支持 ESP32-S3-DevKitC-1-N8R8，再维护约 20–30 个经过来源核对的常用器件。每个器件都必须有精确身份和资料状态，价格作为带日期的采购提示，真实编译/上传/串口观察作为另一条证据链。这样能获得嘉立创“设计—器件—采购”的核心体验，但仍保持个人开发者能维护的规模。

## 来源边界

嘉立创官方文档描述的是其平台当前的功能和流程，不能据此推断个人产品可以调用其商城数据、复制其库内容或获得实时库存授权。若未来要自动读取价格或库存，还需要单独确认公开接口、授权和使用边界。
